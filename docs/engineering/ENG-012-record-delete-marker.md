# 기록 삭제 — delete marker 정책 (확정)

## 지위

**확정 문서다** (2026-08-05 제품 결정). 사용자 가시 동작은 PRD-008 AC-008-06과
PRD-009 AC-009-07이 정의하고, 서버 측 삭제 방식은 본 문서가 단일 소스다.

## 결정

기록 삭제는 물리 삭제(hard delete)가 아니라 **delete marker(soft delete)** 로
처리한다.

- `records`에 삭제 표시(예: `deleted_at TEXT NULL`)를 두고, 삭제 시 현재
  시각을 기록한다. 행 자체와 종속 데이터(공감·댓글·미디어 메타)는 유지한다.
- **모든 조회 경로**(일기 탭, 커뮤니티 피드, 같은 질문 모아보기, 상세 진입,
  책 진행도 집계, AI 서사 입력)는 marker가 찍힌 기록을 제외한다. 예외 없음.
- 사용자 관점 동작은 변하지 않는다: 비가역이며 복구 UI를 제공하지 않는다.
  확인 모달의 "되돌릴 수 없습니다" 문구는 그대로 유효하다 (PRD-008 AC-008-06).
- 첨부 미디어 blob(S3)은 marker 시점에는 지우지 않고 파기 절차에서 함께
  처리한다 ([ENG-005](ENG-005-audio-storage.md)의 저장 구조 참조).

## 근거

- 신고 처리·운영 감사: 신고된 게시글·댓글을 작성자가 삭제해도 운영이 내용을
  확인할 수 있어야 한다 (PRD-009 AC-009-11 접수 이후의 운영 단계).
- 비공개 전환(보존·복구)과 삭제(소멸)의 사용자 대칭을 유지하면서, 서버
  데이터 모델은 하나의 생명주기로 단순화한다.

## 열린 항목 — 파기 기한

**개인정보 파기 기한은 미정이다.** delete marker는 보존을 무기한 허용하는
근거가 아니며, 다음이 결정되어야 한다:

- marker 후 물리 파기까지의 유예 기간 (예: 30일 / 90일)
- 회원 탈퇴 시의 즉시 파기와 본 정책의 관계
- 파기 배치의 실행 주기와 미디어 blob 동시 파기

결정 시 본 문서를 갱신하고 파기 배치를 구현한다. 그 전까지 marker 데이터는
신고 처리 목적 외 접근을 금지한다.
