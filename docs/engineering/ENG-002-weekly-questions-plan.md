# 단계별 질문 — 구현 연기 메모

> **2026-08-08 개정**: PRD-002 의 질문 모델이 임신 주차 전용에서 **아이 단계
> (임신 주차 또는 생후 나이)** 로 일반화됨에 따라 본 메모의 범위도 확장했다.
> 문서 ID(ENG-002)와 파일명은 참조 안정성을 위해 유지한다.

## 요약

PRD-002 의 **AC-002-02 (아이 단계별 질문 매칭)** 본 구현은 **프롬프트 엔지니어링이
끝난 뒤** 별도 작업으로 진행한다. 현재 홈 화면의 "오늘의 질문" 은 단계 무관한
고정 풀에서 day-of-year 로 뽑는 **임시 플레이스홀더** 로 유지한다.

## 현재 상태 (플레이스홀더)

- 구현: [`app/src/data/dailyQuestions.ts`](../../app/src/data/dailyQuestions.ts)
  의 `pickDailyQuestion(date)` — 12개 문항 풀에서 `dayOfYear % N` 인덱스로 선택.
- 단계 무관: `due_date` / `weekLabel` 은 배지 표시에만 쓰이고 (`QuestionCard`),
  질문 선정 로직에는 관여하지 않는다.
- 소비처: [`app/app/(tabs)/index.tsx`](../../app/app/(tabs)/index.tsx) 홈 화면
  Stage 2 질문 카드.

이 구조는 Stage 2 의 UI 기능(코치마크 · AI 미리보기 트리거)을 먼저 검증하기 위한
임시 해결책이며, 단계 기반 매칭 로직은 본 문서의 "본 구현" 단계에서 교체된다.

### 개정된 PRD-002 대비 gap (2026-08-08)

플레이스홀더는 개정 전 PRD-002 기준으로도 AC-002-02 미충족이었고, 개정 후에는
gap 이 하나 늘었다. **의도된 미충족**이며 아래 "본 구현" 에서 함께 해소한다.

| PRD-002 조건 | 플레이스홀더 상태 |
|---|---|
| AC-002-02 단계별 풀 매칭 | ❌ 단계 무관 고정 풀 (기존 gap) |
| AC-002-02 임신·양육 풀 분리 | ❌ 단일 풀 (개정으로 추가된 gap) |
| AC-002-02 반복 방지 | ❌ `dayOfYear % N` 순환 |
| AC-002-05 폴백 (단계 없을 때 공용 풀) | ⚠️ 우연히 충족 — 항상 공용 풀이므로 결과적으로 일치하나, 폴백 **분기가 존재하지 않는다**. 본 구현에서 명시적 분기로 재작성 |
| AC-002-01 단계 표시 | ✅ 배지로 충족 (임신 한정 — 양육 배지는 PRD-007 AC-007-01 구현 범위) |

## 연기 사유

1. **질문 품질이 프롬프트 설계에 의존한다.** 단계별(임신 초기/중기/후기 · 생후
   개월 구간 등) 질문은 "그 시기에만 느낄 수 있는 감정을 포착" (V-001, V-005) 해야 한다.
   이 tone/depth/format 은 하드코딩 풀보다 LLM 생성 + 큐레이션이 적합하고,
   프롬프트가 확정되지 않은 상태에서 문항을 고정하면 나중에 전량 재작성해야 한다.
2. **풀 방식 vs. 생성 방식 결정 미정.** 정적 풀(단계별 고정 문항)로 갈지,
   LLM 이 사용자 컨텍스트(기존 기록, 단계, 계절)를 반영해 매일 생성할지는 프롬프트
   실험 결과에 따라 정해진다. 두 접근의 스키마 · 저장소 · 캐싱 정책이 다르다.
3. **반복 방지 정책도 프롬프트와 묶여 있다.** AC-002-02 의 "같은 질문이
   반복되지 않는다" 는 풀 크기 · 유저별 히스토리 테이블 · 생성 시드에 의존한다.
   프롬프트가 확정되기 전에 스키마를 박으면 손해 본다.

## 본 구현에서 다룰 범위

프롬프트 엔지니어링이 끝난 뒤 별도 PR 로 다음을 수행한다.

- **질문 소스 — 임신 축**: 주차 범위(예: 1–12 · 13–27 · 28–40) 별 프롬프트 확정 →
  생성/풀 중 택1 → 서비스 레이어 추가.
- **질문 소스 — 양육 축**: 생후 나이 구간별 프롬프트 확정. **구간 단위는 2026-08-08
  확정됨** — 1년차 1개월 · 2년차 3개월 · 3년차 6개월 · 4년차 이후 1년
  (PRD-002 "질문 풀 구간" 표, 첫 3년 = 18구간, 반개구간 `[시작, 끝)`).
  본 구현에 남은 것은 **각 구간의 문항 구성**이다. 상한을 두지 않았으므로 문항 제작
  시점에 최상위 흡수 구간(예: n살 이상 통합) 여부를 판단한다.
- **단계 매칭**: ENG-001 의 두 축 산출 결과를 입력으로, 현재 단계가 속한 구간의
  질문을 내려준다. **임신 풀과 양육 풀은 섞이지 않는다** (AC-002-02).
- **폴백 풀 (AC-002-05)**: 단계 없음 판정 시 사용할 단계 무관 공용 풀을 별도로
  구성한다. 현재 플레이스홀더 12문항을 이 폴백 풀의 출발점으로 재활용할 수 있다.
- **반복 방지**: 질문 히스토리 테이블 혹은 결정적 시드로 AC-002-02 의 "같은 질문이
  반복되지 않는다" 를 만족시킨다. 히스토리 키는 **아이 단위** 여야 한다 — 다자녀는
  아이마다 단계가 다르므로 유저 단위 히스토리로는 중복이 샌다.
- **출산 전환 시 히스토리 처리**: 전환(PRD-006 AC-006-06) 으로 아이의 축이 임신 →
  양육으로 바뀔 때, 그 아이의 임신 풀 히스토리를 어떻게 할지 결정 필요.
  **기본 방침은 보존** — 삭제는 되돌릴 수 없고 (오입력 전환을 되돌리면 임신기 질문이
  중복 노출된다), 데이터량이 아이당 수십~수백 행 수준이라 보존 비용이 사실상 없다.
- **플레이스홀더 제거**: `app/src/data/dailyQuestions.ts` 삭제 또는 테스트 전용
  픽스처로 축소.
- **알림 연계 (AC-002-04)**: 푸시 알림 payload 가 단계별 질문을 참조하도록 연결.
  현재 플레이스홀더 단계에서는 알림 본 구현을 시작하지 않는다.
