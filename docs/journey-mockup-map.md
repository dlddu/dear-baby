# 여정 ↔ 목업 매핑 레지스트리

사용자 여정 문서(`docs/journeys/*-journey.md`)가 목업 번들(`docs/index.html`, 소스
`docs/mockups/source/src/screens/`)의 **어느 진입점으로 시각화되는지**를 **기계적으로 확인 가능한
형태**로 등재한다. 흐름의 단일 소스(SSOT)는 여정 문서이고, 이 문서는 여정과 목업을 잇는 **매핑의
SSOT**다 — 매핑을 산문에만 두면 어느 도구도 전수 대조를 할 수 없다.

`scripts/check-journey-mockup-map.mjs` 가 이 문서를 파싱해 규칙 J0~J9 를 강제하고,
`.github/workflows/journey-mockup-map.yml` 이 PR·main push 마다 그 체커를 돌린다.

구현 라우트가 어느 목업을 그리는지(**목업 ↔ 구현** 축)는 이 문서가 아니라
[`mockup-route-map.md`](mockup-route-map.md) 가 담당한다. 사슬은 `여정 문서 → 여정 mockup → 구현 화면`
이고 이 문서가 앞 칸, 그 문서가 뒤 칸이다.

- 여정 총수(실측): **6** — `docs/journeys/*-journey.md` (`README.md` 는 인덱스라 매칭 단위가 아니다)
- 단계 총수(실측): **25** — 각 여정 문서 `## 단계별 상세` 아래 `### Stage …` 헤딩 수
- 목업 카드 총수(실측): **43** — `docs/mockups/source/src/screens/GalleryScreen.tsx` 의 갤러리 인덱스 항목 수
- 갤러리 그룹 총수(실측): **7** — 여정 그룹 6 + 고아 그룹 1(`PRD-009`)

> **왜 숫자를 손으로 적고도 안전한가**: J9 가 이 숫자를 실측값·`docs/mockups/README.md` 일람 표
> 행 수·`docs/doc-tracker.md` 요약 선언과 대조한다. 숫자를 고치는 것이 아니라 **측정 방법을 고정**한
> 것이라, 여정이나 화면이 늘면 체커가 먼저 실패한다.

## 매칭 단위 — 왜 "파일 1개"가 아니라 "갤러리 그룹 1개"인가

이 레포의 목업은 React + Vite 로 빌드된 **단일 HTML 번들 하나**(`docs/index.html`)라 "여정 하나 =
파일 하나"를 물리적으로 만족할 수 없다. 재빌드 파이프라인과 GitHub Pages 진입점이 이미 그 번들
하나로 고정돼 있으므로, 이 레지스트리는 **여정 단위 진입점 = `GalleryScreen.tsx` 의 갤러리 그룹
1개**(`groups[]` 의 한 항목)로 읽는다. 각 그룹은 그 여정의 화면 카드 `M-NN` 을 담는다.

단계 식별자는 여정 문서의 `### Stage …` 헤딩에서 읽는다. 파싱 규칙(체커와 동일):

- 여정 문서에서 `## 단계별 상세` 절만 훑어 `### Stage <id>` 헤딩의 `<id>` 를 뽑는다.
  `<id>` 는 `[0-9]+½?(-[0-9]+)?` — 예: `4` · `6½-2` · `7-4` · `12-1`.
  뒤에 붙는 수식(`(대안)`, `— 제목`, `★ …`)은 식별자가 아니다.
- `## 흐름도` 안의 `### 홈 첫 진입 (Stage 5)` 같은 헤딩은 `### Stage` 로 시작하지 않으므로 집계에
  들어가지 않는다.

## 규칙

| 코드 | 규칙 |
|---|---|
| J0 | **마커 보존** — 아래 다섯 구간의 `begin/end` 마커가 살아 있어야 한다(지우면 그 구간이 통째로 검사에서 빠진다). |
| J1 | **등록 완비** — 모든 여정 문서가 여정 표에 정확히 1행 있다. |
| J2 | **유령 행 금지** — 여정 표의 모든 여정 문서가 실재한다. |
| J3 | **진입점 유일** — 여정 표가 지목한 갤러리 그룹이 실재하고, 두 여정이 같은 그룹을 지목하지 않는다(모델 규칙 1·2). |
| J4 | **카드 집합 일치** — 단계 표가 한 여정에 할당한 카드 집합이 그 갤러리 그룹의 카드 집합과 **양방향으로** 같다(어느 카드도 단계 없이 떠 있지 않다). |
| J5 | **단계 집합 일치** — 단계 표의 단계 집합이 그 여정 문서의 `### Stage …` 집합과 **양방향으로** 같다(모델 규칙 3의 문서 축). |
| J6 | **미시각화 원장** — 대응 카드가 `—` 인 단계 집합이 「미시각화 단계 원장」과 정확히 같고, 원장 행 수가 상한 이하다. 사유 없는 `—` 는 실패. |
| J7 | **고아 원장** — 어느 여정도 지목하지 않은 갤러리 그룹 집합이 「고아 진입점 원장」과 정확히 같고, 상한 이하다(모델 규칙 2). |
| J8 | **구 번호 라벨 원장** — 카드 라벨이 인용한 `Stage <id>` 가 그 카드가 속한 여정 문서에 실재하지 않으면 위반이며, 위반 집합이 「구 번호 라벨 원장」과 정확히 같고 상한 이하다(모델 규칙 6). |
| J9 | **동기화** — `docs/mockups/README.md` 일람 표의 `여정 / Stage` 칸이 이 문서의 할당과 일치하고, 모든 그룹 제목·카드 id 가 번들 `docs/index.html` 에 실재하며(허브 동기화), 집계 4종이 실측·일람 표·`doc-tracker.md` 선언과 모두 같다. |

**래칫으로 동작한다**: J6·J7·J8 은 "등재된 위반은 통과시키되, 등재되지 않은 새 위반도 이미
고쳐졌는데 원장에 남은 공전 행도 실패"다. 상한(`*-cap`)은 낮추는 방향으로만 고친다.

## 5. 구 번호 라벨 원장

목업 카드의 `PhoneFrame` 라벨은 `M-NN · <여정> · Stage <id>` 형식으로 단계를 인용하는데, 그
`<id>` 상당수가 **여정 문서에 존재하지 않는 구 번호 체계**다. 카드 43장 중 41장이 단계를 인용하고,
그중 34장이 자기 여정 문서에 없는 식별자를 가리킨다.

가장 위험한 형태는 **여정을 가로지르는 충돌**이다 — `M-31`~`M-34`(Book Production)의 라벨은
`Stage 9-1`~`9-4` 를 인용하는데, 그 번호는 문서상 AI Narrative 의 것이고 Book Production 은
`10-1`~`11` 이다. 즉 라벨만 보면 **다른 여정의 실재 단계를 가리켜** 조용히 잘못 대조된다.

체커는 카드가 속한 여정 문서를 기준으로 판정한다(전체 여정의 합집합이 아니다). 따라서 아래
원장이 비는 것이 곧 라벨 체계가 문서와 붙었다는 뜻이며, 그 정정은 `data-journey`/`data-step`
속성 도입·번들 재빌드와 함께 하는 후속 슬라이스의 일이다(아래 「후속」).

## 아직 기계 검증하지 못하는 것 (후속)

이 레지스트리는 **문서 축**(여정·단계·카드의 대응)까지만 기계화한다. 남은 축은 목업 쪽에
식별자가 없어 판정할 수단 자체가 없다.

| 모델 규칙 | 현재 상태 | 필요한 것 |
|---|---|---|
| 3 단계 집합 일치(목업 축) | 판정 불가 | 화면 컴포넌트에 `data-journey`/`data-step` 속성 도입 → 문서 25단계와 목업 단계 집합의 양방향 대조. **소스 43장 수정 + 번들 재빌드**가 함께 필요하다. |
| 4 분기 대응 | 판정 불가 | 온보딩 Case A/B/C, 출산 전환 대안 경로가 갤러리에서 **선택 가능한 이동**이어야 한다(현재는 카드 태그 표기뿐). |
| 5 흐름 체험 가능 | 미충족 | 여정 진입점 안에서 단계 전환 수단·현재 위치 표시·`#<step-id>` 딥링크·분기 선택. 현재 갤러리는 카드 격자라 "여정 하나를 걸어보는" 동선이 없다. |
| 6 참조 무결성(라벨 축) | 위반 34건 등재 | 라벨의 구 번호를 문서 식별자로 정정(§5) + 슬러그 체계(`JRN-<슬러그>`/`STP-<슬러그>`)로의 이관. 번호 기반 식별자는 단계가 추가·재배치되면 통째로 어긋난다. |

후속 작업은 위 넷을 **한 번의 소스 수정 + 재빌드**로 묶는 것이 비용상 유리하다(라벨을 고치는 김에
`data-*` 를 넣고 슬러그로 이관하면 파일·문자열 변경이 한 번으로 끝난다).

## 갱신 규약

- 여정 문서를 추가·삭제하면 §1 에 행을 넣고 §2 에 그 단계 행을 전부 넣는다. 진입점을 두지 않기로
  하면 §1 의 갤러리 그룹 칸을 `—` 로 두고 `docs/doc-tracker.md` 의 「여정 mockup 예외」에 사유와
  재검토 시점을 등재한다.
- 갤러리에 카드를 추가하면 §2 의 어느 단계에든 넣는다(J4 가 떠 있는 카드를 잡는다). 소스를 고쳤으면
  **반드시 재빌드해 같은 커밋에 `docs/index.html` 을 담는다** — J9 의 허브 동기화 검사가 이를 잡는다.
- 단계를 없앨 때 식별자를 재사용하지 않는다. 여정 문서의 변경 이력에 폐기 사실을 남긴다.
