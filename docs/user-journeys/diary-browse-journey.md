# Diary Browsing Journey — 누적된 기록을 다시 만나는 여정

> 사용자가 일기 탭에 들어와 과거 자신이 남긴 기록을 다시 보고, 다듬고, 정리하는 여정. Daily Recording Journey의 **곁가지 루프**로, 작성과 같은 빈도로 발생하지 않지만 **V-001 (감정 보존)을 진짜 보존으로 완성하는** 결정적 통로다.
>
> 일기 탭은 다른 탭과 달리 **활성 아이로 분리되지 않으며**, 사용자가 작성한 모든 아이의 기록을 시간 축 하나로 통합해서 보여준다. 회상의 시간은 단일이고, 사용자 정체성도 단일이기 때문이다.

## 개요

일상 기록 루틴(Stage 6)이 **"작성"** 행위라면 본 여정은 **"재방문"** 행위다. 사용자는 다음과 같은 비주기적 트리거로 일기 탭에 들어온다.

- 며칠/몇 주 전 한 마디를 떠올리고 싶을 때 (감정적 회상)
- 작성 직후 미처 정리하지 못한 오타·문장을 다듬고 싶을 때 (사후 편집)
- 비공개로 둔 기록을 가족과 공유하고 싶어 공개로 전환할 때 (공개 토글)
- 너무 사적이라 후회되는 기록을 비공개·삭제하려고 할 때 (정리·삭제)
- AI 서사 생성을 앞두고 "어느 정도 모였지?" 확인하고 싶을 때 (누적 점검)
- 출산 임박 / 책 만들기 직전, 임신 기간 전체를 훑어보고 싶을 때 (회고)
- (다자녀) "두 아이 기록이 비슷한 양으로 쌓이고 있나?" 공평성 점검 (PRD-008의 통합 표시가 이 점검을 즉시 가능하게 함)

이 여정의 매끄러움이 **V-001 (감정 보존)의 진짜 완성도**를 결정한다. 작성만 잘 되고 다시 찾기 어렵다면, "보존됐다"는 사용자의 체감은 깨진다.

## 핵심 설계 결정 — 통합 표시

본 여정의 가장 큰 설계 결정은 **일기 탭이 활성 아이로 분리되지 않는 것**이다 (PRD-008 AC-008-01).

| 다른 탭 (홈·커뮤니티·자서전) | 일기 탭 (본 여정) |
|---|---|
| 활성 아이 단위로 화면 재구성 | **모든 아이 통합 표시** |
| 헤더에 활성 아이 이름 + 좌우 전환 ◀ ▶ | 헤더에 `일기` 타이틀만 (전환 없음) |
| 다자녀는 아이별로 책 진행도·질문이 다름 | 다자녀도 한 화면에서 두 아이 기록 모두 시간순 |
| 사용 모드: "지금 이 아이에게" | 사용 모드: "내가 쓴 기록 전부" |

이 결정의 근거:

1. **사용자 정체성은 단일** — 사용자(엄마)는 한 명이고 모든 기록을 자신이 썼다
2. **회상의 시간 축은 하나** — "그때 무슨 일이 있었지?"라고 떠올릴 때 시간은 절대축
3. **공평한 노출** — 아이별로 분리되면 새 아이 기록만 보고 다른 아이 기록을 잊기 쉬움

다자녀가 특정 아이만 보고 싶을 때는 일기 탭 내 **아이 필터**(PRD-008 AC-008-08)로 분리한다. 즉, 기본은 "전부 통합", 필요할 때만 "특정 아이로 좁히기".

## 단계별 상세

### `STP-diary-enter` 일기 탭 진입

| 축 | 내용 |
|---|---|
| **사용자 행동** | 하단 네비에서 일기 탭(📓) 탭. 진입 즉시 모든 아이의 기록이 시간 순으로 통합된 목록을 본다. 다른 탭에서 어느 아이가 활성이었든 일기 탭에는 영향 없다 |
| **사용자 감정·생각** | "그때 내가 뭐라고 했지?" / "쟁여둔 기록이 이만큼이구나" / (Case B 다자녀) "콩이 기록과 하준 기록이 한 화면에 같이 있네 — 비슷하게 쌓이고 있나?" |
| **시스템 응답** | **PRD-008 / AC-008-01** — 모든 아이 기록 통합 표시, 활성 아이 컨텍스트 비적용 / **AC-008-10** — 일기 탭 전용 헤더(`일기` + 🔔), 좌우 화살표 없음 / **AC-008-09** — 기록 0건이면 안내 + `홈으로 가기` CTA |
| **페인포인트 / 기회** | ⚠️ 신규 사용자가 기록 0건 상태로 들어오면 빈 화면 인상 → 🌱 빈 상태 카피와 홈 CTA가 첫 작성으로 부드럽게 유도 / 🌱 (다자녀) 통합 표시 자체가 공평성 점검 도구로 기능 — 한 아이 기록이 다른 아이보다 적으면 시각적으로 즉시 인지 |

### `STP-diary-scroll` 월 그룹 스크롤과 아이 필터

| 축 | 내용 |
|---|---|
| **사용자 행동** | 목록을 스크롤하며 월 그룹 헤더(`📅 2025년 11월`)로 시간 위치를 가늠한다. 카드마다 우상단에 아이 컨텍스트 칩(`🌱 콩이 · 임신 28주차` 등)이 있어 어느 아이 기록인지 즉시 식별. 특정 아이만 보고 싶으면 ⚙ 필터에서 아이를 선택, 특정 시기·미디어를 좁히려면 기간·미디어 필터를 함께 사용 |
| **사용자 감정·생각** | "11월 즈음에 그 이야기를 했었지" / "사진 첨부한 것만 보고 싶다" / (다자녀) "하준 기록만 좀 모아보자" / "지난 한 달치만 훑어보자" |
| **시스템 응답** | **AC-008-02** — 월 단위 sticky 그룹 헤더 / **AC-008-03** — 카드 우상단 아이 컨텍스트 칩(모드 이모지 + 아이 이름 + 작성 시점 컨텍스트) / **AC-008-08** — 필터 시트(아이[다자녀만]·기간·미디어 칩·공개 여부), 적용 시 즉시 갱신, 필터 배지로 적용 상태 노출 |
| **페인포인트 / 기회** | ⚠️ 기록이 100건+ 누적되면 시간 스크롤만으로는 못 찾음 → 🌱 필터(특히 아이·기간)가 누적 사용자에게 필수 도구 / ⚠️ 통합 표시에서 한 아이 기록이 다른 아이를 압도하면 다른 아이 기록을 못 보고 지나칠 위험 → 🌱 카드 아이 칩이 시각적 구분, 추가로 아이별 색상 톤 부여 검토(후속) |

| 축 | 내용 |
|---|---|

| **페인포인트 / 기회** | ⚠️ 미디어 로딩 지연으로 감정 흐름 깨짐 → 🌱 텍스트 우선 표시, 미디어 progressive 로딩 (후속 검토) / 🌱 음성 원본 재생이 **본 여정에서 가장 감정적인 모먼트** — 텍스트로는 못 살린 떨림·웃음을 복원한다 |

| 축 | 내용 |
|---|---|

| **페인포인트 / 기회** | ⚠️ 삭제 후 후회 ("그래도 남겨둘 걸") → 🌱 후속 검토 — N일간 휴지통 복구 / ⚠️ 사후 편집이 작성 시 음성-텍스트 정합성을 깨뜨릴 수 있음 → 🌱 음성 원본은 불변으로 보호 / 🌱 삭제 모달의 아이 이름 치환이 "어느 아이 책에 영향?"을 명확히 알려줌 |

```
                          (재현) (정리)
```

> **이 곡선의 의미**: 본 여정의 정서적 정점은 **"음성 원본 재생"** 모먼트다. 텍스트만으로는 못 살리는 그 시점 자기 목소리의 떨림·웃음·울먹임이 V-001 (감정 보존)을 비로소 "보존됐다"로 체감하게 한다. 반대 극은 삭제 직전 망설임 — 비가역 동작의 안전장치(아이 이름 치환 카피)가 사용자 신뢰를 결정한다.

- **V-003 (서사 부여)**는 월 단위 시간 그룹이 만드는 **준-서사** 효과 — AI 서사 생성(플로우 4) 이전에도 시간 축 정리만으로 일부 서사 효과를 제공한다
- **V-007 (멀티미디어)**는 작성(플로우 2)에서 수집되고, 본 여정의 상세 화면에서 비로소 "다시 본다·다시 듣는다"라는 형태로 가치가 실현된다

## Daily Recording Journey와의 관계

본 여정은 [Daily Recording Journey](daily-recording-journey.md)와 **시간 축이 다르다**.

- Daily Recording: 매일 / 매주 정기적 (푸시 알림이 트리거, 활성 아이별)
- Diary Browsing (본 여정): 비주기적, 사용자 내적 동기로만 진입, **모든 아이 통합**

따라서 푸시 알림 같은 시스템적 동력이 없다. 본 여정의 진입은 사용자가 **"다시 만나고 싶다"**, **"다듬고 싶다"**, **"공유하고 싶다"**는 내적 동기에 전적으로 의존한다. 이는 본 여정의 매끄러움이 사용자 체감 만족도에 직접 영향을 준다는 뜻이다 — 한 번 들어와서 원하는 동작이 막히면 다음 진입까지의 간격이 길어지고, 그게 길어지면 **V-001 보존의 체감 가치**가 사라진다.

또한 작성 여정은 활성 아이별로 분리되어 진행되지만, 회상 여정은 통합된다 — 이 비대칭이 본 PRD의 설계 핵심이다.
