# PRD-008: 일기 탭 — 내 기록 조회 및 관리

## 개요

디어베이비의 하단 네비게이션 5탭 중 4번째 탭으로, **사용자가 자신이 작성한 모든 기록을 다시 보고 관리하는 화면**이다. 홈 탭이 "오늘 기록한다"는 행위에 집중한다면, 일기 탭은 "쌓아둔 기록을 본다·고친다·정리한다"는 행위에 집중한다.

이 탭은 다음 두 가지 책임을 가진다.

1. **조회 책임**: 사용자가 작성한 **모든 아이의 기록을 통합**해서 시간 순으로 보여주고, 한 기록을 탭하면 텍스트와 미디어를 포함한 상세 화면을 연다.
2. **사후 관리 책임**: 작성 직후가 아니라 며칠/몇 주가 지난 시점에 기록을 편집·삭제·공개 여부 변경할 수 있게 한다.

기록 **작성** 동작은 [PRD-001](PRD-001-voice-diary.md)이, **미디어 첨부** 동작은 [PRD-005](PRD-005-media-records.md)가, **활성 아이 컨텍스트**는 [PRD-006](PRD-006-onboarding-cases.md)이, **홈 탭의 헤더·하단 네비게이션** 시각 명세는 [PRD-007](PRD-007-home-screen.md)이 정의한다. 본 PRD는 그것들을 "이미 작성된 기록을 다시 본다"는 사용자 시점에 맞춰 일기 탭 화면에 어떻게 배치·연결할지를 정의한다.

본 PRD는 [PRD-001 AC-001-05 (기록 목록 조회)](PRD-001-voice-diary.md)의 상위 화면 명세이며, 해당 AC를 흡수·확장한다. PRD-001 AC-001-05는 본 PRD가 발효된 시점부터 본 PRD의 AC-008-02 ~ AC-008-04를 가리키는 것으로 해석한다.

### 활성 아이 컨텍스트와의 관계 (중요)

일기 탭은 **다른 탭과 달리 활성 아이로 분리되지 않는다**. 사용자는 한 화면에서 자신이 쓴 모든 기록(여러 아이의 기록 포함)을 시간 순으로 만난다. 이는 다음 이유에서 의도된 설계 결정이다.

- **사용자 정체성은 단일**: 한 사용자(엄마)가 여러 아이의 기록을 모두 작성하므로, "내가 쓴 기록 전부"라는 단일 흐름이 자연스럽다
- **회상의 시간 축은 하나**: 사용자가 "그때 무슨 일이 있었지?"라고 떠올릴 때, 시간은 절대축이지 아이별로 분리되지 않는다 (특히 동시기에 양육·임신을 같이 하는 Case B)
- **공평한 노출**: 아이별로 분리되면 새 아이 기록만 보고 다른 아이 기록을 잊기 쉽다. 통합 표시는 다자녀 양육자의 공평성 부담을 덜어준다

다자녀 사용자가 특정 아이의 기록만 보고 싶을 때는 **AC-008-08 필터**의 "아이 선택"으로 분리해서 볼 수 있다.

이 결정은 [PRD-006 AC-006-09](PRD-006-onboarding-cases.md)에서 "일기 탭도 활성 아이 기준으로 동작"한다고 명세된 부분을 갱신한다 — 일기 탭은 활성 아이 컨텍스트의 영향을 받지 않는 예외 탭이다.

## 제공 가치

- **V-001 (감정 보존)**: 작성 시점의 감정이 시간이 지나도 다시 찾아 읽을 수 있어야 비로소 영구적 보존이 완성된다. 일기 탭은 "기록을 다시 만나는 통로"다.
- **V-002 (기록의 부담 제거)**: 사후 편집·삭제·공개 토글이 한 화면에서 가능해, 작성 시점에 "완벽하게 써야 한다"는 부담을 줄여준다. "일단 말하고 나중에 다듬기" 패턴을 지지한다. 다자녀 양육자에게는 아이별 탭 전환 없이 한 곳에서 모든 기록을 만나는 단순함을 제공한다.
- **V-003 (서사적 의미 부여)**: 월 단위 시간 그룹핑으로 흩어진 기록이 시간 축 위에 정리되어 보이고, 그 누적 자체가 사용자에게 "이만큼이 모였구나"라는 서사적 감각을 준다. AI 서사 생성 전이라도 시간 축 정리만으로 일부 서사 효과를 제공한다.
- **V-007 (멀티미디어 감정 표현)**: 작성 시 첨부했던 사진·영상·음성 메모를 다시 재생·열람할 수 있어, 텍스트만으로 사라질 감정을 다층적으로 보존한다.

## Acceptance Criteria

### AC-008-01: 모든 아이의 기록 통합 표시

- **설명**: 일기 탭은 사용자가 작성한 모든 아이의 기록을 단일 시간 축으로 통합해서 표시한다. 다른 탭에서 활성 아이가 무엇이든 일기 탭의 목록은 영향을 받지 않는다
- **달성 가치**: V-001, V-002
- **참조**: [PRD-006 AC-006-09](PRD-006-onboarding-cases.md) (본 AC가 그 명세를 갱신)
- **조건**:
  - 사용자가 작성한 **모든 기록**(임신 중 작성한 것 + 양육 중 작성한 것 + 모든 아이에게 작성한 것)을 한 목록에 통합해서 표시한다
  - 다른 탭(홈·커뮤니티·자서전)의 활성 아이 컨텍스트가 변경되어도 일기 탭의 목록은 갱신되지 않는다
  - 일기 탭 진입 직전 활성 아이 컨텍스트는 일기 탭이 노출하는 헤더와 목록 어디에도 영향을 주지 않는다
  - 단일 아이 사용자에게도 동일한 통합 표시가 적용된다 (즉, 단일 아이라도 카드에 아이 컨텍스트 칩이 표시된다 — AC-008-03)
  - 다자녀 사용자가 "특정 아이만 보기"가 필요한 경우는 [AC-008-08 필터](#ac-008-08-필터--아이날짜미디어공개-여부)의 아이 선택을 사용한다
  - 본 AC는 사용자 정체성을 단일로 보고 시간 축을 하나로 유지한다는 설계 결정에 따른다 (개요 참조)

### AC-008-02: 기록 목록 — 월 단위 시간 그룹

- **설명**: 기록은 최신순으로 정렬되고, **달력 월 단위**의 그룹 헤더로 묶여서 표시된다
- **달성 가치**: V-003
- **조건**:
  - 정렬 기준: **기록 작성일 내림차순** (가장 최근에 작성한 기록이 최상단)
  - 그룹 헤더 형식: `📅 YYYY년 MM월` (예: `📅 2025년 11월`)
  - 동일 달력 월에 작성된 모든 기록(어느 아이 기록이든)이 하나의 그룹 아래에 묶인다
  - 같은 그룹 내에서는 카드도 작성일 내림차순으로 정렬된다
  - 그룹 헤더는 목록에서 sticky하게 동작하여, 스크롤 중에도 현재 보고 있는 기록의 그룹이 상단에 고정 표시된다
  - 한 번에 로드하는 카드 수는 **20개**를 기본으로 하며, 하단 스크롤 시 추가 로드한다 (정확한 페이지 크기·로딩 indicator 디자인은 후속)
  - 그룹 헤더는 카드 시각 위계보다 약하게 표시되어 콘텐츠의 호흡 단위로만 기능한다 (구체 시각은 디자인 시스템 따름)
  - **임신 주차·생후 개월수·나이** 같은 아이별 컨텍스트는 그룹 키로 사용되지 않으며, 각 카드 안에서 표시된다 (AC-008-03)

### AC-008-03: 기록 카드 — 아이 컨텍스트 칩과 표시 요소

- **설명**: 목록의 각 기록 카드는 한 화면에서 다수 기록을 식별 가능한 최소 정보를 표시하며, 각 기록이 **어느 아이에게 작성된 것인지**를 항상 보여준다
- **달성 가치**: V-001, V-002
- **조건**:
  - 각 카드는 다음 요소로 구성된다:
    - **좌측 상단 — 작성 날짜**: `MM/DD (요일)` 형식 (예: `11/22 (금)`)
    - **우측 상단 (1행) — 아이 컨텍스트 칩**: `<이모지> <아이 이름> · <작성 시점 컨텍스트>` 형식
      - 임신 중 작성: `🌱 콩이 · 임신 28주차`
      - 양육 중 작성 (12개월 이하): `👶 하준 · 생후 5개월`
      - 양육 중 작성 (13개월 이상): `🧒 서연 · 2살`
      - 이모지는 임신/양육 모드를 시각적으로 구분하는 보조 표식이다 (정확한 이모지·아이 색상 톤은 디자인 단계에서 확정)
    - **우측 상단 (2행) — 공개 여부 배지**: `🔒 비공개` 또는 `🌐 공개`. 작성 시점의 공개 설정을 반영하되 사후 변경 가능 (AC-008-07)
    - **본문 상단 — 질문 텍스트**: 작성 시점에 답한 [오늘의 질문](PRD-002-daily-questions.md) 텍스트. `Q.` 접두어로 시작하고 1줄(말줄임)로 표시
    - **본문 하단 — 답변 미리보기**: 답변 본문의 첫 약 60자, 이후 `...`로 말줄임. `A.` 접두어로 시작 (정확한 글자 수는 디자인 단계에서 카드 폭에 맞춰 조정)
    - **하단 — 미디어 아이콘 행**: 첨부된 미디어가 있으면 아이콘+개수로 표시
      - 사진: `🖼️ ×N` (N이 1이면 개수 생략 가능)
      - 영상: `🎬 ×N`
      - 음성 메모: `🎙️` (개수 표시 없이 존재만)
      - 첨부 0건이면 미디어 행 자체를 표시하지 않는다
  - 아이 컨텍스트 칩은 단일 아이 사용자에게도 동일하게 표시된다 (디자인 일관성 + 사용자가 아이를 추가하는 미래 상황 대비)
  - 칩의 컨텍스트는 **작성 시점 기준**이지 현재 시점 기준이 아니다 (시간 축 무결성)
  - 질문이 없는 기록(사용자가 자유 기록으로 작성한 경우)은 `Q.` 행을 생략하고 답변 미리보기만 표시한다
  - 카드를 탭하면 기록 상세 화면(AC-008-04)으로 진입한다
  - 카드 자체에서는 편집·삭제 액션 노출 없음 (상세 화면에서만 가능 — 비가역 동작 안전성 우선)

### AC-008-04: 기록 상세 — 진입과 전체 표시

- **설명**: 카드를 탭하면 해당 기록의 전체 텍스트와 미디어를 보여주는 상세 화면으로 진입한다
- **달성 가치**: V-001, V-007
- **참조**: [PRD-005 AC-005-01 ~ AC-005-07](PRD-005-media-records.md) (미디어 재생/표시)
- **조건**:
  - 상세 화면은 별도 화면으로 push 전환된다 (back 버튼으로 일기 탭 목록으로 복귀, 스크롤 위치 유지)
  - 상단에 다음 메타 정보가 표시된다:
    - 작성 날짜 — `YYYY년 MM월 DD일 (요일)` 형식 (예: `2025년 11월 22일 (금)`)
    - 작성 시점의 아이 컨텍스트 칩 — AC-008-03과 동일한 형식 (예: `🌱 콩이 · 임신 28주차`)
    - 공개 여부 배지 (AC-008-03의 배지와 동일)
  - 본문은 다음 순서로 표시된다:
    - **질문**: 작성 시점에 답한 질문 (있는 경우). 1인칭 시점, 본문보다 약간 작은 폰트, 인용 스타일 표기
    - **답변 본문**: 전체 텍스트 (말줄임 없음, 줄바꿈 보존)
    - **첨부 미디어**: 사진/영상은 풀-블리드 또는 정사각 그리드로 표시. 영상은 인라인 재생 가능. 음성 메모는 재생 컨트롤(▶️ 재생/일시정지·진행 바·총 길이) 형태로 표시. 미디어 동작 상세는 PRD-005 따름
  - 상세 화면 우상단에 **`⋯` (더보기) 버튼**이 노출된다. 탭하면 액션 시트가 하단에서 슬라이드 업으로 열리며 다음 항목을 노출한다:
    - 편집 (AC-008-05)
    - 삭제 (AC-008-06)
    - 공개로 전환 / 비공개로 전환 (현재 상태의 반대 액션 라벨로 표시. AC-008-07)
    - 취소
  - 음성 원본이 있는 기록은 답변 본문 위에 작은 텍스트로 "음성 원본 있음 · 재생" 링크가 추가 노출된다 (PRD-005 AC-005-05 참조)

### AC-008-05: 기록 편집 — 사후 편집

- **설명**: 작성 시점 이후에도 기록 본문과 첨부 미디어를 수정할 수 있다
- **달성 가치**: V-001, V-002
- **참조**: [PRD-001 AC-001-03 (변환 텍스트 편집)](PRD-001-voice-diary.md), [PRD-005 (미디어 통합)](PRD-005-media-records.md)
- **조건**:
  - 상세 화면 `⋯` 메뉴의 **편집** 진입점에서 시작된다
  - 편집 화면에서 다음 항목을 변경할 수 있다:
    - 답변 본문 텍스트 (PRD-001 AC-001-03의 편집 UX 그대로 사용)
    - 첨부 미디어의 추가·제거·순서 변경 (PRD-005의 첨부 UX 그대로 사용)
    - 공개/비공개 설정 (AC-008-07과 동일한 토글 UI)
  - 변경 불가능한 항목 (작성 시점에 결정되어 그대로 유지):
    - 작성 일자 — 기록의 시간 축 무결성을 위해 사후 변경 금지
    - 작성 시점의 질문 — 답변과 질문의 결합 관계를 유지하기 위해 변경 금지
    - 작성 시점의 아이 컨텍스트 (대상 아이 + 그 시점의 임신 주차/개월수) — 시간 축 정합성을 위해 변경 금지. 사용자는 사후 편집에서 "이 기록을 다른 아이에게 옮기기"를 할 수 없다 (작성 시점의 의도를 보존)
    - 음성 원본 파일 (PRD-005 AC-005-05 무결성 원칙 준수)
  - 편집 완료 시 변경 사항이 저장되고 상세 화면으로 복귀한다
  - 편집 취소 시 변경 사항은 폐기되며 사용자에게 "수정 사항이 저장되지 않았습니다" 확인 모달이 한 번 표시된다 (변경이 있었을 경우에만)
  - 편집 이력 자체는 본 PRD 범위 외 (후속 검토)

### AC-008-06: 기록 삭제 — 확인 모달

- **설명**: 사용자는 개별 기록을 삭제할 수 있으며, 삭제 전 명시적 확인을 거친다
- **달성 가치**: V-002
- **조건**:
  - 상세 화면 `⋯` 메뉴의 **삭제** 진입점에서 시작된다
  - 삭제 탭 시 확인 모달이 열리며 다음 정보가 표시된다:
    - 제목: `이 기록을 정말 삭제할까요?`
    - 본문: `삭제하면 기록 본문과 첨부 미디어가 모두 사라지고, [아이 이름]의 책에도 포함되지 않게 됩니다. 이 동작은 되돌릴 수 없습니다.`
      - 본문 카피의 `[아이 이름]`은 그 기록이 작성된 대상 아이의 이름으로 치환된다 (사용자가 어느 아이의 책에 영향을 주는지 인지하도록)
      - 삭제 대상이 공개 상태의 기록이면 본문에 `받은 공감과 댓글도 함께 삭제됩니다.` 문장이 추가된다
    - 버튼: `취소` (회색, 기본 포커스) / `삭제` (코랄, 위험 강조 색상)
  - 사용자가 `삭제`를 탭하면:
    - 기록과 모든 첨부 미디어가 삭제된다 — 사용자 관점에서 비가역이며 복구 수단을 제공하지 않는다 (서버 측 삭제 방식은 [ENG-012 delete marker 정책](../engineering/ENG-012-record-delete-marker.md)을 따르며, 휴지통·복구 UI는 본 PRD 범위 외 — 후속 검토)
    - 상세 화면을 빠져나와 일기 탭 목록으로 복귀하며, 목록에서 해당 카드가 즉시 사라진다
    - **그 기록이 작성된 대상 아이의 책 진행도**(PRD-007 AC-007-07의 n/50)에서 1 차감된다. 다른 아이의 책 진행도는 영향 받지 않는다
    - 토스트 메시지로 `기록이 삭제되었습니다`가 약 2초간 표시된다
  - 삭제된 기록은 커뮤니티(타인 기록 피드)에서도 즉시 제거되며, 누적된 공감·댓글도 모든 사용자 화면에서 함께 소멸한다 — 비공개 전환(AC-008-07)의 보존·복원과 달리 삭제는 복구 경로가 없다 (공개였던 경우, PRD-009 AC-009-07 참조)
  - 다중 선택 삭제는 본 PRD 범위 외 (후속 검토)

### AC-008-07: 공개/비공개 토글 — 사후 변경

- **설명**: 사용자는 기록의 공개 여부를 작성 후에도 변경할 수 있으며, 변경은 즉시 반영되어 커뮤니티 피드 노출 여부에도 영향을 준다
- **달성 가치**: V-002
- **참조**: [PRD-009 AC-009-07 (공개 수명주기)·AC-009-05 (모아보기 열람 권한)](PRD-009-community-tab.md)
- **조건**:
  - 다음 두 진입점에서 동일한 동작을 수행한다:
    - 상세 화면 `⋯` 메뉴의 **공개로 전환** / **비공개로 전환** (현재 상태의 반대 액션)
    - 편집 화면 내 공개/비공개 토글 (AC-008-05)
  - 비공개 → 공개로 전환 시:
    - 즉시 커뮤니티 노출 대상에 포함된다 (화면·카드는 [PRD-009 AC-009-02·14](PRD-009-community-tab.md), 노출 풀·정렬은 ENG-007~010 소관)
    - 사용자에게 토스트 `이 기록이 다른 사용자에게 공개됩니다`가 표시된다
  - 공개 → 비공개로 전환 시:
    - 즉시 커뮤니티 피드에서 제거된다
    - 이미 다른 사용자가 본 화면에서 표시 중이던 카드는 다음 새로고침 시 사라진다 (서버 측 동기화)
    - 해당 질문의 "같은 질문 답변 모아보기" 열람 권한도 즉시 소멸한다 — 열람 권한은 현재 공개 상태 기준이다 ([PRD-009 AC-009-05](PRD-009-community-tab.md) 참조)
    - 사용자에게 토스트 `이 기록이 비공개로 전환되었습니다`가 표시된다
  - 공개 기록에 누적된 공감(하트) 수는 비공개 전환 시에도 데이터로 유지되며, 재공개 시 그대로 복원된다 (사용자 손실 방지)
  - 공개 기본값은 **비공개**다 (작성 시점 선택은 [PRD-001 AC-001-06](PRD-001-voice-diary.md) 참조. 기본값의 사용자 변경 기능은 설정 탭 보류에 따라 범위 외)

### AC-008-08: 필터 — 아이·날짜·미디어·공개 여부

- **설명**: 사용자가 통합 목록에서 특정 아이 / 시기 / 미디어 / 공개 여부의 기록만 빠르게 좁혀 볼 수 있는 필터를 제공한다. 다자녀 사용자에게는 "아이 선택" 필터가 가장 중요한 도구다
- **달성 가치**: V-002
- **조건**:
  - 일기 탭 상단의 **⚙️ 필터 아이콘**을 탭하면 하단 시트로 필터 패널이 슬라이드 업된다
  - 필터 항목 (상단 순서대로):
    - **아이 필터**: 사용자가 등록한 모든 아이가 칩으로 표시되며 다중 선택 가능 (예: `🌱 콩이` / `👶 하준` / `🧒 서연`). 선택 없으면 전체 표시
      - 아이가 **1명**인 사용자에게는 본 필터 항목 자체를 시트에서 노출하지 않는다 (단일 아이는 선택이 무의미)
    - **기간 필터**: `전체` / `최근 1개월` / `최근 3개월` / `사용자 지정 (시작일 ~ 종료일)`
    - **미디어 필터**: 칩 다중 선택 — `사진 포함` / `영상 포함` / `음성 메모 포함` (선택 없으면 전체 표시)
    - **공개 여부 필터**: `전체` / `공개만` / `비공개만`
  - 필터 적용 시 목록이 즉시 갱신되고, 적용된 필터 개수가 ⚙️ 아이콘 우상단에 작은 배지로 표시된다 (예: `⚙️²`)
  - 필터 패널 하단에 `초기화` / `적용` 버튼이 표시된다
  - 일기 탭을 이탈했다가 다시 진입하면 필터는 **초기화**된다 (앱 세션 단위로만 유지)
  - 텍스트 검색은 본 AC에 포함되지 않으며, 후속 검토 항목에서 다룬다

### AC-008-09: 빈 상태 처리

- **설명**: 기록이 0건이거나 필터 결과가 0건일 때, 사용자에게 안내 메시지와 다음 행동 진입점을 명확히 보여준다
- **달성 가치**: V-002
- **조건**:
  - **기록이 0건인 경우** (필터 미적용 상태, 어느 아이의 기록도 없음):
    - 화면 중앙에 일러스트(또는 이모지 `📓`)와 함께 다음 카피가 표시된다:
      - 메인: `아직 첫 기록이 없어요`
      - 보조: `홈에서 오늘의 질문에 답해보세요. 한 마디면 충분해요.`
    - 그 아래에 `홈으로 가기` CTA 버튼이 표시된다 (탭 시 홈 탭으로 전환)
  - **필터 결과가 0건인 경우** (기록은 있지만 필터로 걸러진 상태):
    - 화면 중앙에 이모지(`🔍`)와 함께 다음 카피가 표시된다:
      - 메인: `조건에 맞는 기록이 없어요`
      - 보조: `필터를 조정하거나 초기화해보세요.`
    - 그 아래에 `필터 초기화` CTA 버튼이 표시된다 (탭 시 필터 초기화 + 목록 갱신)
  - 어느 빈 상태에서도 헤더와 하단 네비게이션 바는 그대로 노출된다 (다른 탭 이동 가능)

### AC-008-10: 일기 탭 헤더 + 하단 네비게이션 바

- **설명**: 일기 탭은 홈 탭과 의도적으로 다른 헤더를 가진다 — 활성 아이 컨텍스트가 적용되지 않는 탭이므로 좌우 화살표·아이 이름이 노출되지 않는다. 하단 네비게이션은 PRD-007 AC-007-10을 그대로 준수한다
- **달성 가치**: V-001, V-002, V-006
- **참조**: [PRD-007 AC-007-10](PRD-007-home-screen.md), [PRD-006 AC-006-09](PRD-006-onboarding-cases.md)
- **조건**:
  - **일기 탭 헤더 구성**:
    - 좌측: 빈 영역 (홈 탭의 ◀ 화살표가 노출되지 않는다)
    - 중앙: `일기` 타이틀 (font-display 또는 동등 강조)
    - 우측: 🔔 알림 아이콘 (PRD-007 AC-007-03의 동작 규칙 동일 — 안 읽은 알림 있으면 red dot 노출, 탭 시 알림 목록 화면 이동)
  - 일기 탭 헤더는 어느 아이 정보도 표시하지 않는다 (활성 아이가 누구든 영향 없음)
  - **하단 네비게이션 바**: 5탭 구성·라벨·순서·시각 강조 규칙 모두 [PRD-007 AC-007-10](PRD-007-home-screen.md)과 동일
  - 일기 탭(4번)이 현재 선택된 탭으로 시각적으로 강조된다
  - 다른 탭으로 전환 시 본 화면의 스크롤 위치는 유지되고, 필터 상태는 AC-008-08 규칙에 따라 초기화된다

## 후속 검토 항목

본 PRD 작성 시점에 다음 항목은 미정으로, 후속 작업에서 확정한다.

- **텍스트 검색**: 기록 본문·질문 키워드를 텍스트로 검색하는 기능. AC-008-08 필터와 통합할지, 별도 검색 화면으로 분리할지 후속 결정.
- **휴지통과 복구**: AC-008-06의 삭제는 현재 영구 삭제로 정의했으나, 사용자 실수 보호를 위한 N일간 복구 가능 휴지통 도입 여부.
- **다중 선택 삭제**: 일기 탭 목록에서 다수 기록을 한 번에 선택해 삭제하는 흐름. 누적 정리 시점에 유용하지만 디자인 복잡도 증가 → 후속.
- **편집 이력 추적**: 사후 편집(AC-008-05)이 잦은 사용자를 위해 변경 이력을 보여주는지 여부.
- **AC-008-03 아이 컨텍스트 칩 시각 디테일**: 임신/양육 모드 이모지 (`🌱`/`👶`/`🧒`)와 아이별 색상 톤 — 디자인 단계에서 확정. 다자녀에서 아이 식별이 빠르도록 아이마다 고유 색상을 부여할지 검토.
- **AC-008-03 답변 미리보기 글자 수 (약 60자)**: 디자인 단계에서 실제 카드 폭·글자 크기와 함께 조정.
- **AC-008-02 페이지 크기 (20개)**: 실제 사용자 데이터 기반으로 적정 페이지 크기 재산정.
- **음성 원본 재생 위치**: AC-008-04에서 상세 화면 상단에 인라인 노출했으나, 텍스트 본문 옆 또는 별도 미디어 섹션 안으로 이동할지 디자인 검토.
- **타임라인/캘린더 뷰**: 현재는 list 뷰만 정의. 캘린더로 보는 대안 뷰 도입 여부.
