# PRD-002: 매일 다른 질문 알림

## 개요

아이의 현재 단계에 맞는 의미 있는 질문을 매일 제공하여 사용자가 기록할 소재를 자연스럽게 떠올릴 수 있도록 돕는 기능이다. "오늘의 질문"을 통해 기록의 방향을 제시하고, 기록 습관을 형성한다.

본 PRD는 질문의 **모델(무엇이 질문을 정의하는가)** 과 **전달(어떻게 매일 도달하는가)** 을 정의한다.
질문 카드의 화면 배치·회전 UI는 [PRD-007](PRD-007-home-screen.md), 커뮤니티에서의 질문 노출은 [PRD-009](PRD-009-community-tab.md) 소관이다.

> **2026-08-08 개정**: 질문 모델이 임신 주차 전용이었던 것을 **아이 단계(임신 주차 또는 생후 나이)** 로 일반화했다. 개정 사유와 범위는 아래 "개정 배경" 참조.

## 제공 가치

- **V-001 (감정 보존)**: 단계별 맞춤 질문으로 그 시기에만 느낄 수 있는 감정을 포착한다
- **V-002 (기록의 부담 제거)**: "무엇을 기록할지" 고민하는 부담을 질문이 대신 해결한다
- **V-005 (아이 단계별 맞춤 질문)**: 아이의 현재 단계에 따라 의미 있는 질문을 매일 제공한다

## 개정 배경 (2026-08-08)

개정 전 PRD-002는 질문을 **임신 주차 전용**으로 정의했다. 그러나 제품의 나머지 부분은 이미 임신·양육 두 단계를 모두 다루고 있었다.

| 문서 | 개정 전 상태 |
|---|---|
| PRD-006 AC-006-06 | 출산 전환 시 "임신 주차 기반 컨텍스트 → 양육 일수 기반 컨텍스트" 갱신을 이미 규정 |
| PRD-007 AC-007-01 | 헤더 컨텍스트를 임산부(`00주차`/`D-00`)·양육자(`mm개월`/`nn살`) 양쪽으로 이미 규정 |
| PRD-008 AC-008-03 | 기록 카드 칩에 `임신 28주차`·`생후 5개월`을 이미 병기 |
| ENG-011 | 유사 시기 반경을 임신 ±4주 / 생후 ±1개월로 이미 확정 |
| **PRD-002 · V-005 · 용어집 · ENG-002** | **임신 전용으로 잔존 — 개정 대상** |

즉 Case C(순수 양육자) 사용자와 출산 전환을 마친 Case A·B 사용자는 질문 모델상 **대상이 정의되지 않은 상태**였다. 본 개정은 이 공백을 닫는다. 화면·커뮤니티 쪽 명세는 이미 양쪽을 다루고 있었으므로 변경하지 않는다.

## 질문 모델

오늘의 질문은 다음 속성으로 정의된다. **단계는 선택 속성이 아니라 기본 속성이다** — 질문은 항상 특정 단계를 향해 던져진다.

| 속성 | 필수 | 설명 |
|---|---|---|
| 대상 아이 | ✅ | 질문이 향하는 아이. 다자녀는 활성 아이 (PRD-006 AC-006-09) |
| **단계 (stage)** | ✅ | **임신 주차** 또는 **생후 나이** 중 하나. 두 값을 동시에 갖지 않는다 |
| 질문 텍스트 | ✅ | 아이 1인칭 시점 문장 (PRD-007 AC-007-04) |
| 안내 문구 | | 질문 의도를 짧게 덧붙이는 마이크로카피 |

### 단계의 두 축

| 케이스 | 단계 축 | 기준값 | 산출 |
|---|---|---|---|
| 임신 중 | 임신 주차 | 출산 예정일 (`due_date`) | [ENG-001](../engineering/ENG-001-pregnancy-week-calc.md) |
| 양육 중 | 생후 나이 | 생년월일 (`birth_date`) | [ENG-001](../engineering/ENG-001-pregnancy-week-calc.md) |

- **두 축은 배타적이다.** 한 아이는 어느 시점에나 둘 중 하나의 단계에만 속한다. 출산 전환(PRD-006 AC-006-06)이 축을 바꾸는 유일한 사건이다.
- **케이스 혼합 금지.** 임신 단계 질문 풀과 양육 단계 질문 풀은 섞이지 않는다 (ENG-011의 케이스 경계 원칙과 동일).
- **표시 형식은 PRD-007 AC-007-01을 따른다.** 본 PRD는 단계가 질문 모델에 포함된다는 사실만 규정하고, `28주차`/`D-36`/`5개월 (152일째)`/`2살 (430일째)` 같은 표기 형식은 중복 정의하지 않는다.

### 질문 풀 구간 (2026-08-08 확정)

단계는 연속값이지만 질문 풀은 **구간(bucket)** 단위로 구성한다. 구간이 곧 "이 시기용 질문 묶음"의 단위다.

**임신 축** — 주차 단위. 세부 구간 묶음(초기/중기/후기 등)은 ENG-002 본 구현 범위.

**양육 축** — 시간이 지날수록 변화 속도가 느려지므로 구간 폭을 단계적으로 넓힌다.

| 티어 | 범위 | 구간 폭 | 구간 수 |
|---|---|---|---|
| 1년차 | 생후 0개월 ~ 12개월 미만 | **1개월** | 12 |
| 2년차 | 12개월 ~ 24개월 미만 | **3개월** | 4 |
| 3년차 | 24개월 ~ 36개월 미만 | **6개월** | 2 |
| 4년차 이후 | 36개월 이상 | **1년** | (상한 없음) |

- 첫 3년이 **18개 구간**이고, 이후 매년 1개씩 늘어난다.
- **구간은 반개구간 `[시작, 끝)`이다.** 정확히 12개월인 아이는 1년차의 마지막 구간이 아니라 **2년차의 첫 구간**에 속한다.
- 개월 수는 [ENG-001](../engineering/ENG-001-pregnancy-week-calc.md)의 **달력 기준** 산출을 따른다 (30일 나눗셈 아님).
- **근거**: 신생아기는 한 달마다 아이가 달라지지만 세 살 이후에는 반년이 지나도 질문의 결이 크게 달라지지 않는다. 균일 구간으로 두면 초기엔 질문이 뭉툭해지고 후기엔 문항 제작 비용만 늘어난다.

> **표기 전환 임계와 구간 경계는 별개다.** PRD-007 AC-007-01의 표기 전환은 `12개월 이하 → 개월 / 13개월 이상 → 살`이고, 본 표의 티어 경계는 `12개월`이다. 두 숫자가 어긋나 보이지만 **의도된 것**이다 — 표기 형식(사용자에게 어떻게 보이는가)과 풀 구간(어느 문항 묶음에서 뽑는가)은 서로 독립적인 관심사다. 한쪽에 맞춰 다른 쪽을 "고치지" 말 것.

### 단계 스냅샷

기록에 저장되는 단계는 **작성 당시**의 단계다 (ENG-011의 "유사도 기준 시점"과 동일 원칙). 지금 30주차인 사용자가 20주차에 남긴 답변은 영구히 20주차 기록이다.

**저장 방식은 물리 저장 + 기준값 정정 시 재계산으로 확정됐다** (2026-08-08). 상세는 [ENG-013](../engineering/ENG-013-stage-snapshot-persistence.md).

단계는 `f(작성일, 기준값)` 의 결과이고 작성일은 불변이므로, 스냅샷은 **순수 함수의 캐시**다. 여기서 두 가지가 따라 나온다.

| 변화 | 스냅샷 | 이유 |
|---|---|---|
| **시간 경과** | 변하지 않음 | 함수의 입력이 안 바뀐다. 30주차가 되어도 20주차 기록은 20주차 |
| **출산 전환** | 변하지 않음 | 축이 바뀌는 것은 아이의 *현재* 단계이지 과거 기록이 아니다 (ENG-011) |
| **기준값 정정** (예정일·출생일 수정) | **재계산됨** | 함수의 입력이 바뀌었다. 오타로 잘못 찍힌 주차는 정정되는 것이 옳다 |

세 번째 행이 "불변"과 충돌하는 것처럼 보이지만 그렇지 않다. 불변인 것은 **그때 무슨 일이 있었는가**(작성일)이고, 정정되는 것은 **그것을 몇 주차라 부를 것인가**(기준값 해석)다.

## Acceptance Criteria

### AC-002-01: 오늘의 질문 표시

- **설명**: 홈 화면에 오늘의 질문이 대상 아이의 단계와 함께 표시된다
- **달성 가치**: V-005
- **조건**:
  - 홈 화면에서 오늘의 질문 카드가 보인다
  - **활성 아이의 단계 정보가 함께 표시된다** — 임신 중이면 임신 주차, 양육 중이면 생후 나이 (표기 형식은 PRD-007 AC-007-01)
  - 질문에 대한 짧은 안내 문구가 포함된다
  - 단계를 산출할 수 없는 경우의 처리는 AC-002-05를 따른다

### AC-002-02: 아이 단계별 질문 매칭

- **설명**: 대상 아이의 현재 단계에 맞는 질문이 자동으로 선택된다
- **달성 가치**: V-005, V-001
- **조건**:
  - **임신 중인 아이**: 출산 예정일 기반으로 현재 임신 주차를 산출하고, 해당 주차에 적합한 질문 풀에서 선택한다
  - **양육 중인 아이**: 생년월일 기반으로 현재 생후 나이를 산출하고, 해당 시기에 적합한 질문 풀에서 선택한다
  - **두 풀은 섞이지 않는다** — 임신 중 아이에게 양육 단계 질문이, 양육 중 아이에게 임신 단계 질문이 노출되지 않는다
  - 매일 새로운 질문을 제공하며, 같은 질문이 반복되지 않는다
  - 다자녀의 경우 활성 아이의 단계를 기준으로 한다 (PRD-006 AC-006-09)
  - 출산 전환(PRD-006 AC-006-06) 직후부터 해당 아이의 질문은 양육 단계 풀에서 선택된다

> **구현 상태**: 본 AC의 본 구현은 프롬프트 엔지니어링 완료 후로 연기되어 있다 ([ENG-002](../engineering/ENG-002-weekly-questions-plan.md)). 현재 홈의 질문은 단계 무관 고정 풀에서 뽑는 플레이스홀더이며, 이는 본 AC 미충족 상태로 ENG-002에 등재되어 있다.

### AC-002-03: 질문에서 기록으로 연결

- **설명**: 질문을 보고 바로 해당 질문에 대한 기록을 시작할 수 있으며, 기록에는 질문과 작성 당시 단계가 함께 남는다
- **달성 가치**: V-002
- **조건**:
  - 질문 카드에서 바로 음성 기록 또는 텍스트 기록을 시작할 수 있다
  - 기록 시 해당 질문이 함께 저장된다
  - **기록에는 작성 당시의 단계가 함께 남는다** — 저장 시점에 계산해 물리 저장한다 ([ENG-013](../engineering/ENG-013-stage-snapshot-persistence.md))
  - 저장된 단계는 **시간이 지나거나 출산 전환이 일어나도 변하지 않는다** (임신 중 작성분은 출산 이후에도 임신 단계 기록으로 유지)
  - 단, **기준값(예정일·출생일)이 정정되면 해당 아이의 같은 축 기록 스냅샷이 재계산된다** — 오입력으로 잘못 기록된 단계는 정정을 따라간다 (트리거 전량은 ENG-013)
  - 단계를 산출할 수 없는 상태에서 작성된 기록은 스냅샷이 비어 있다 (AC-002-05)

### AC-002-04: 질문 알림 발송

- **설명**: 매일 정해진 시간에 오늘의 질문을 푸시 알림으로 보낸다
- **달성 가치**: V-002
- **조건**:
  - 사용자가 설정한 시간에 푸시 알림이 발송된다
  - 알림이 참조하는 질문은 발송 시점의 활성 아이 단계에 매칭된 질문이다 (AC-002-02)
  - 알림을 탭하면 해당 질문 화면으로 이동한다
  - 알림 시간을 사용자가 변경할 수 있다
  - 아이가 둘 이상이어도 알림은 1회만 발송한다 (PRD-006 AC-006-05의 중복 발송 방지 원칙과 동일)

### AC-002-05: 단계 산출 불가 시 폴백

- **설명**: 대상 아이의 단계를 산출할 수 없는 경우, 단계 무관 공용 질문 풀로 폴백하고 단계 표시를 생략한다
- **달성 가치**: V-002
- **조건**:
  - 다음 경우 단계를 산출할 수 없는 것으로 본다 (판정 기준은 [ENG-001](../engineering/ENG-001-pregnancy-week-calc.md))
    - 출산 예정일 미입력 — 온보딩의 "아직 정해지지 않았어요" 탈출구 (PRD-006 AC-006-02)
    - 기준값이 유효 범위를 벗어남 (예: 5주 이상 지난 예정일)
  - 이 경우 **단계 무관 공용 풀**에서 질문을 선택한다
  - 질문 카드에서 **단계 표시만 생략**한다 — 질문 자체는 정상 노출되며, 기록 진입(AC-002-03)도 정상 동작한다
  - 단계 표시 생략은 홈 헤더 컨텍스트 배지 숨김(ENG-001 경계값 정책)과 동일한 조건에서 일어난다
  - 사용자가 이후 기준값을 입력하면 다음 질문부터 단계별 풀로 복귀한다
  - 이 상태에서 남긴 기록은 단계 없는 기록으로 저장되며, 커뮤니티 유사 시기 추천(ENG-011)의 반경 내 그룹에 들지 않는다

## 비기능 요구사항

- **단계 갱신 시각**: 단계는 시스템 날짜 기준으로 매일 자동 갱신된다. 기준 시각은 사용자 단말의 로컬 타임존을 따른다 (PRD-006 비기능 요구사항과 동일)
- **폴백의 가시성**: AC-002-05의 폴백은 사용자에게 오류나 결함으로 보이지 않아야 한다. 단계 배지가 없을 뿐 질문 경험은 동일하다
