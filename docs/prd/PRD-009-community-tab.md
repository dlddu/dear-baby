# PRD-009: 커뮤니티 탭 — 공개 기록 기반 공감 커뮤니티

> ✅ **확정 (2026-08-05)** — 원문은 최서영의 「0704 커뮤니티(WIP) 기획안」이며, 2026-07-15에
> draft로 편입된 뒤 2026-08-05 결정 세션에서 미확정 지점을 전수 결정하여 확정했다
> (결정 원장: claude-docs `20260805-dear-baby-prd-009-decisions`). 노출 로직(정렬·노출 풀·
> 페이지네이션·본인 기록)은 의도적으로 AC 밖에 두고 ENG-007~010 초안이 관리하며, 확정 시
> 재개발한다. 해소 내역은 문서 말미 [미확정 항목 해소 이력](#미확정-항목-해소-이력)에 있다.

## 개요

디어베이비의 하단 네비게이션 5탭 중 2번째 탭으로, **비슷한 임신/육아 시기를 보내는
사용자들이 서로의 공개 기록을 읽고 공감하는 공간**이다.

홈 화면의 "다른 엄마들의 기록" 섹션(본 PRD [AC-009-14](#ac-009-14-홈-다른-엄마들의-기록-섹션--이관-수용) —
구 PRD-007 AC-007-08에서 이관)이 맛보기(최대 3개 카드)라면, 커뮤니티 탭은 그 전체
화면이다. 홈 섹션의 **">더보기"** 링크와 피드 카드 탭이 이 탭으로 진입한다.

원문 기획안이 정의한 기능 목적은 다음과 같다.

| 목적 | 설명 |
|------|------|
| 공감 형성 | 사용자가 다른 엄마들의 기록을 보며 "나만 이런 게 아니구나"를 느끼게 함 |
| 기록 지속 유도 | 다른 사람의 답변을 보는 경험이 사용자의 일기 작성 동기를 높임 |
| 콘텐츠 축적 | 공개 기록이 쌓이면서 서비스 내 감성 콘텐츠 자산 형성 |
| 장기 수익화 기반 | 커뮤니티 체류 시간, 재방문, 콘텐츠 소비를 기반으로 향후 광고/제휴/프리미엄 기능 확장 가능 |

### 핵심 설계 결정

1. **별도 글쓰기가 없는 커뮤니티**: 커뮤니티에는 사용자가 새 글을 작성하지 않는다.
   콘텐츠는 전부 기존 기록(AI 질문 답변·자유 일기) 중 사용자가 **커뮤니티 공개**로
   설정한 것이다. 커뮤니티 탭에 글쓰기 버튼을 제공하지 않는다.
2. **정보성 ✖️ 공감 ⭕**: 1차에서는 공감성 글만 다룬다. 정보성 글 허용은 추후 검토.
3. **상호 공개(reciprocity)**: "같은 질문 답변 모아보기"는 내 답변을 공개한 사용자만
   열람할 수 있다. 공개가 공개를 부르는 구조로 콘텐츠 축적을 유도한다.
4. **텍스트 전용 1차**: 개인정보 보호·운영 리스크·MVP 범위 축소를 위해 1차 런치에서는
   사진을 커뮤니티에 노출하지 않는다.
5. **용어는 "공감"**: 서비스 톤상 사용자 화면에서 `좋아요`가 아닌 `공감` 표현을 쓴다
   (내부 데이터명은 `like`).

## 제공 가치

- **V-008 (공감을 통한 연결)**: 커뮤니티 탭은 이 가치의 주 구현체다. 원문 기획안의
  1순위 목적 "공감 형성"("나만 이런 게 아니구나")이 곧 V-008이며, 유사 시기 추천·
  공개 기록 피드·같은 질문 답변 모아보기·공감·댓글이 모두 이 연결감을 만드는 장치다.
  홈 화면의 "다른 엄마들의 기록" 섹션(AC-009-14)이 맛보기로 제공하는 것을 전면화한다.
- **V-002 (기록의 부담 제거)**: 커뮤니티는 "기록 지속 유도"에도 기여한다. 내 글에
  달리는 공감/댓글과 답변 유도 CTA가 일기 작성 동기를 높인다. 별도 글쓰기 없이 기존
  기록의 공개 전환만으로 참여할 수 있어 커뮤니티 참여 자체의 부담도 없고, 익명 공개·
  개인정보 비노출 정책은 "공개해도 안전하다"는 심리적 안전망으로 공개 전환의 부담을
  낮춘다.
- **V-005 (아이 단계별 맞춤 질문)**: "오늘의 질문 카드"와 "같은 질문 답변 모아보기"는
  같은 질문에 다른 엄마들이 어떻게 답했는지 보여줌으로써 질문 하나의 가치를 증폭한다.
  유사 시기 자동 추천은 현재 아이 컨텍스트(임신 주차/생후 개월)에 맞는 기록을 우선
  노출한다.

> 원문의 "공감 형성" 목적은 본 PRD 편입을 계기로 신설된 **V-008 (공감을 통한 연결)**
> 에 매핑한다 (2026-07-15, 기존 tracker 검토 항목 "커뮤니티 가치의 가치 문서 추가
> 여부" 해소). "콘텐츠 축적"·"장기 수익화 기반"은 사용자 가치가 아닌 사업 목표이므로
> 가치 문서에 올리지 않는다.

## Acceptance Criteria

### AC-009-01: 콘텐츠 출처 — 공개 기록 기반, 별도 글쓰기 없음

- **설명**: 커뮤니티 콘텐츠는 사용자가 **커뮤니티 공개**로 설정한 기존 기록만으로 구성되며, 커뮤니티 탭에서 새 글을 작성할 수 없다
- **달성 가치**: V-002, V-008
- **참조**: [PRD-001 AC-001-06 (작성 시점 공개 설정)·AC-001-07 (임시 저장)](PRD-001-voice-diary.md), [PRD-008 AC-008-07 (공개/비공개 토글)](PRD-008-diary-tab.md)
- **조건**:
  - 커뮤니티에 노출되는 콘텐츠 유형은 다음 규칙을 따른다:

    | 콘텐츠 유형 | 커뮤니티 노출 여부 |
    |------------|-------------------|
    | AI 질문 답변 | 공개 설정 시 노출 |
    | 자유 일기 | 공개 설정 시 노출 |
    | 비공개 기록 | 미노출 |
    | 삭제된 기록 | 미노출 ([ENG-012](../engineering/record-delete-marker.md) delete marker 기준) |
    | 임시 저장 기록 | 미노출 — 서버 미전송 로컬 상태라 구조적으로 노출 불가 ([AC-001-07](PRD-001-voice-diary.md)) |

  - 커뮤니티 탭에는 별도의 `글쓰기` 버튼을 제공하지 않는다
  - 공개/비공개 선택은 기록 작성 시([AC-001-06](PRD-001-voice-diary.md), **기본값 비공개**)와 사후 관리(일기 탭 [AC-008-05·07](PRD-008-diary-tab.md)·게시글 상세 AC-009-07)에서 가능하다
  - 공개 설정 시 안내 문구 예시: *"비슷한 시기를 보내는 엄마들에게 작은 공감이 될 수 있어요. 익명으로 공개할까요?"*

### AC-009-02: 커뮤니티 메인 화면 구조와 피드 카드

- **설명**: 커뮤니티 메인 화면은 혼합형 구조(헤더·유사 시기 영역·오늘의 질문 카드·타입 필터·공개 기록 피드)로 구성되고, 피드 카드는 공개 기록의 요약 정보를 표시한다
- **달성 가치**: V-002, V-008
- **조건**:
  - 메인 화면은 위에서부터 ① 상단 헤더 ② 나와 비슷한 엄마들의 기록 영역 ③ 오늘의 질문 카드 ④ 콘텐츠 타입 필터 ⑤ 공개 기록 피드 순으로 구성된다
  - 피드 카드는 다음 요소로 구성된다:

    | 요소 | 설명 |
    |------|------|
    | 커뮤니티 표시명 | 마스킹된 표시명 (AC-009-10 규칙, 예: `seo***1`) |
    | 아이 현황 | 임신 주차 또는 생후 개월 수 |
    | 콘텐츠 타입 | 질문답변/자유일기 구분 |
    | 질문 텍스트 | AI 질문 답변인 경우 표시 |
    | 제목 | 자유 일기인 경우 표시 |
    | 본문 미리보기 | 최대 2~3줄 노출 |
    | 공감 수 | 하트 아이콘 + 숫자 |
    | 댓글 수 | 댓글 아이콘 + 숫자 |
    | 작성일 | 필요 시 상세 화면에서 노출 |

  - 피드 카드를 탭하면 게시글 상세 화면(AC-009-07)으로 이동한다
  - 피드에 **어떤 기록이 어떤 순서로** 노출되는지(노출 풀·기본 정렬·페이지네이션·본인
    기록 포함 여부)는 본 AC의 검증 범위가 아니다 — 미확정 초안
    [ENG-008](../engineering/community-feed-exposure-pool.md)·[ENG-007](../engineering/community-feed-default-sort.md)·[ENG-009](../engineering/community-feed-pagination.md)·[ENG-010](../engineering/community-feed-own-records.md)이
    관리하고, 유사 시기 가중치만 [ENG-011](../engineering/community-similar-stage-recommendation.md)로 확정되어 있다

### AC-009-03: 상단 필터 — 유사 시기 자동 추천

- **설명**: 메인 상단에 현재 선택된 아이 기준 상태값이 표시된다. 유사 시기 우선 노출의 정의는 ENG-011이 담당한다
- **달성 가치**: V-008
- **참조**: [PRD-006 AC-006-09 (활성 아이 컨텍스트)](PRD-006-onboarding-cases.md), [ENG-011 (유사 시기 추천 — 확정)](../engineering/community-similar-stage-recommendation.md)
- **조건**:
  - 상단에 현재 선택된 아이 기준의 상태값을 표시한다:

    | 사용자 상태 | 표시 문구 |
    |------------|----------|
    | 임산부 | 임신 20주차 |
    | 양육자 | 생후 5개월 |
    | 다자녀 | 현재 홈에서 선택된 아이 기준 |

  - 활성 아이 전환 시 상태값과 추천 기준이 전환된 아이로 갱신된다 ([AC-006-09](PRD-006-onboarding-cases.md): 커뮤니티 탭은 선택된 아이의 케이스·주차 컨텍스트로 진입)
  - **1차 런치에서는 사용자가 직접 필터를 변경하는 기능을 제공하지 않고**, 현재 선택된 아이 상태 기준으로 자동 추천한다 (임산부/양육자 상세 필터는 후순위)
  - "비슷한 시기"의 정의와 적용은 [ENG-011](../engineering/community-similar-stage-recommendation.md)을 따른다 (**확정**: 반경 임신 ±4주/생후 ±1개월 · 케이스 혼합 금지 · 기록의 **작성 당시** 단계 기준 · 하드 필터가 아닌 정렬 가중치). 본 AC의 검증 범위는 상태값 표시·아이 전환 갱신·수동 필터 미제공까지이며, 우선 노출 순서 자체의 검증은 ENG-011과 기본 정렬(ENG-007) 확정 이후의 재개발 범위다

### AC-009-04: 오늘의 질문 카드 — CTA 상태 분기

- **설명**: 메인 상단에 오늘의 질문 카드를 노출하고, CTA는 내 답변 상태에 따라 세 갈래로 분기한다
- **달성 가치**: V-002, V-005, V-008
- **참조**: [PRD-002 (매일 다른 질문)](PRD-002-daily-questions.md), [PRD-007 AC-007-04~06 (홈 질문 카드)](PRD-007-home-screen.md)
- **조건**:
  - 카드는 다음 요소로 구성된다:

    | 요소 | 설명 |
    |------|------|
    | 라벨 | 오늘의 질문 |
    | 질문 텍스트 | 홈과 동일한 오늘의 질문 (현재는 [ENG-002](../engineering/weekly-questions-plan.md) 고정 풀 플레이스홀더) |
    | 안내 문구 | 내 답변을 공개하면 같은 질문에 답한 기록을 볼 수 있어요 |
    | CTA 버튼 | 다른 엄마들의 답변 보기 |

  - CTA 클릭 시 동작은 내 답변 상태에 따라 분기한다:

    | 내 답변 상태 | 동작 |
    |-------------|------|
    | 아직 답변하지 않음 | 질문 답변 화면으로 이동 |
    | 답변했지만 비공개 | 공개 전환 유도 팝업 노출 |
    | 답변했고 공개 | 같은 질문 답변 모아보기 화면으로 이동 |

  - 카드의 목적은 사용자가 같은 질문에 답한 다른 엄마들의 기록을 보도록 유도하는 것이다
  - **전제 (확정)**: 본 AC와 AC-009-05는 오늘의 질문이 사용자 간 공유(`question_id` 동일)됨을
    전제한다. 현재 질문은 [ENG-002](../engineering/weekly-questions-plan.md) 고정 풀(사용자 간
    동일)이므로 전제가 성립하며, **현 상태를 가정하고 확정**한다. ENG-002 본 구현에서 질문
    생성 방식이 사용자별로 달라지는 안이 채택되면 본 AC·AC-009-05의 모아보기 전제를 재검토한다

### AC-009-05: 같은 질문 답변 모아보기 — 상호 공개 기반 열람

- **설명**: 특정 AI 질문에 대한 공개 답변을 모아 보여주되, 내 답변을 공개한 사용자만 열람할 수 있다
- **달성 가치**: V-005, V-008
- **참조**: [PRD-008 AC-008-07 (사후 전환)](PRD-008-diary-tab.md), [ENG-002 (질문 풀 — AC-009-04의 전제 공유)](../engineering/weekly-questions-plan.md)
- **조건**:
  - 열람 권한은 상호 공개 기반으로 운영한다:

    | 상태 | 열람 권한 |
    |------|----------|
    | 내 답변 없음 | 열람 불가 |
    | 내 답변 비공개 | 전체 열람 불가, 공개 전환 유도 |
    | 내 답변 공개 | 전체 열람 가능 |

  - 비공개 상태 안내 문구 예시: *"다른 엄마들은 이 질문에 어떻게 답했을까요? 내 답변을 익명으로 공개하면 같은 질문에 답한 기록을 볼 수 있어요."*
  - 안내 화면/팝업의 버튼은 다음과 같이 제공한다:

    | 버튼 | 동작 |
    |------|------|
    | 내 답변 공개하고 보기 | 기존 답변을 공개 상태로 전환한 뒤 같은 질문 답변 목록으로 이동 |
    | 나중에 볼게요 | 팝업 또는 안내 화면 닫기 |

  - 공개 전환 시 기존 답변의 공개 여부가 `public`으로 변경되며, 해당 답변은 커뮤니티 피드에도 노출된다
  - **열람 권한은 현재 공개 상태 기준이다**: 이후 답변을 다시 비공개로 전환하면 모아보기 열람 권한도 즉시 소멸한다 — "한 번 공개했던 이력"은 권한을 남기지 않는다 ([AC-008-07](PRD-008-diary-tab.md)의 전환 동작과 정합)

### AC-009-06: 콘텐츠 타입 필터

- **설명**: 메인 피드에 전체/질문답변/자유일기 필터를 제공한다
- **달성 가치**: V-008
- **조건**:
  - 필터 항목과 동작:

    | 필터 | 설명 |
    |------|------|
    | 전체 | AI 질문 답변 + 자유 일기 전체 |
    | 질문답변 | AI 질문 답변만 노출 |
    | 자유일기 | 자유 일기만 노출 |

  - 기본 선택값은 `전체`이다

### AC-009-07: 게시글 상세 화면 — 본인 글 관리와 공개/비공개 수명주기

- **설명**: 피드 카드에서 진입하는 상세 화면은 기록 전체와 반응(공감·댓글)을 보여주고, 본인 글에는 관리 기능을 제공하며, 공개 상태 변화가 커뮤니티 노출에 즉시 반영된다
- **달성 가치**: V-002, V-008
- **참조**: [PRD-008 AC-008-04~07 (상세·편집·삭제·공개 토글)](PRD-008-diary-tab.md)
- **조건**:
  - 상세 화면 표시 요소:

    | 요소 | 설명 |
    |------|------|
    | 작성자 표시명 | 마스킹된 커뮤니티 표시명 (AC-009-10) |
    | 아이 현황 | 임신 주차/생후 개월 |
    | 작성일 | 기록 작성일 기준 |
    | 콘텐츠 타입 | 질문답변/자유일기 |
    | 질문 텍스트 | AI 질문 답변인 경우 |
    | 제목 | 자유 일기인 경우 |
    | 본문 전체 | 사용자가 작성한 답변/일기 전체 |
    | 공감 버튼 | 중복 불가, 취소 가능 |
    | 댓글 영역 | 댓글 및 대댓글 표시 |
    | 신고 버튼 | 부적절한 게시글 신고 |

  - 내가 작성한 글인 경우 다음 기능을 제공한다:

    | 기능 | 설명 |
    |------|------|
    | 공개/비공개 전환 | 상세 화면에서 공개 상태 변경 가능 |
    | 본문 수정 | 일기 상세/기록 상세 화면으로 연결 |
    | 삭제 | 기록 삭제 가능 |

  - 공개 상태와 커뮤니티 노출의 관계:

    | 상태 | 커뮤니티 노출 |
    |------|--------------|
    | 나만 보기 | 미노출 |
    | 커뮤니티 공개 | 노출 |
    | 공개 → 비공개 전환 | 커뮤니티에서 제거 |
    | 비공개 → 공개 전환 | 커뮤니티에 노출 |
    | 삭제 | 커뮤니티에서 제거 |

  - 비공개 전환 시 해당 기록은 커뮤니티 피드와 같은 질문 답변 모아보기 화면에서 **즉시 제거**된다
  - 단, 비공개 전환 시 기존 공감/댓글 데이터는 삭제하지 않고 보존한다. 이후 다시 공개 전환할 경우 기존 공감/댓글 데이터가 함께 복구된다
  - **삭제 시**에는 게시글과 누적 공감·댓글이 모든 사용자 화면에서 함께 소멸하며 복구 경로가 없다 — 비공개 전환(보존·복원)과 대칭되는 소멸 동작이다. 확인 모달·비가역 규정은 [AC-008-06](PRD-008-diary-tab.md), 서버 측 처리는 [ENG-012 delete marker](../engineering/record-delete-marker.md)를 따른다

### AC-009-08: 공감

- **설명**: 사용자는 피드 카드 또는 상세 화면에서 공감을 누를 수 있다
- **달성 가치**: V-002, V-008
- **조건**:
  - 서비스 톤상 사용자 화면에서는 `좋아요`보다 `공감` 표현을 사용한다
  - 공감 정책:

    | 항목 | 정책 |
    |------|------|
    | 기능명 | 공감 |
    | 내부 데이터명 | like |
    | 중복 공감 | 불가 |
    | 공감 취소 | 가능 |
    | 본인 글 공감 | 불가 |
    | 표시 방식 | 하트 아이콘 + 카운트 |

  - **본인 글 공감 불가는 도달 경로와 무관하게 적용된다** — 커뮤니티 피드, 같은 질문 답변 모아보기, 일기 탭을 경유한 상세 진입 등 어떤 화면에서 본인 기록에 도달해도 동일하다 (피드 내 본인 기록 노출 여부([ENG-010](../engineering/community-feed-own-records.md), 미확정)와 무관하게 성립)
  - 댓글 공감(AC-009-09)에도 동일 정책을 적용한다: 본인이 작성한 댓글에는 공감할 수 없다

### AC-009-09: 댓글/대댓글 — 1depth 제한

- **설명**: 게시글 상세 화면에서 댓글을 작성할 수 있고, 대댓글은 1depth까지만 허용한다
- **달성 가치**: V-002, V-008
- **조건**:
  - 댓글 정책:

    | 항목 | 정책 |
    |------|------|
    | 댓글 작성 | 가능 |
    | 작성자 표시 | 게시글과 동일 — 마스킹된 커뮤니티 표시명 (AC-009-10 준용) |
    | 원글 작성자 배지 | 원글 작성자가 단 댓글에는 `작성자` 배지 표시 |
    | 이미지 첨부 | 1차 런치 제외 |
    | 댓글 공감 | 가능 (본인 댓글 제외 — AC-009-08 준용) |
    | 대댓글 | 1depth까지만 허용 |
    | 대댓글의 대댓글 | 불가 |
    | 댓글 삭제 | 작성자 본인만 가능 |
    | 댓글 수정 | 1차 런치 제외 |

  - 대댓글은 댓글에 대한 답글까지만 허용하며, 그 이하 단계의 답글은 제공하지 않는다

### AC-009-10: 개인정보·사진 노출 보호 정책

- **설명**: 커뮤니티에는 개인 식별 가능성이 높은 정보와 사진을 노출하지 않는다 (1차)
- **달성 가치**: V-002
- **참조**: [PRD-005 (미디어 첨부)](PRD-005-media-records.md)
- **조건**:
  - 개인정보 노출 정책:

    | 정보 | 노출 여부 |
    |------|----------|
    | 커뮤니티 표시명 (마스킹) | 노출 |
    | 아이 현황 | 노출 |
    | 임신 주차 | 노출 |
    | 생후 개월 수 | 노출 |
    | 작성일 | 노출 가능 |
    | 실제 이름 | 비노출 |
    | 아이 이름/태명 | 비노출 |
    | 출산 예정일 | 비노출 |
    | 실제 생년월일 | 비노출 |
    | 이메일/소셜 계정 정보 | **원문 비노출** — 아래 규칙의 마스킹 파생 표시명만 허용 |

  - **커뮤니티 표시명 규칙 (확정 2026-08-05)**: 게시글·댓글 작성자는 항상 마스킹된 커뮤니티 표시명으로 표시한다
    - 원본: 사용자 **이메일의 로컬파트** (`@` 앞부분, `users.email` — NOT NULL이라 모든 계정에서 산출 가능)
    - 마스킹: **앞 3자 + `***` + 끝 1자** (예: `seoyeon1@…` → `seo***1`). 로컬파트가 4자 이하이면 **첫 1자 + `***`**
    - 이메일 도메인은 어떤 형태로도 노출하지 않으며, 마스킹 결과에서 원본 이메일을 복원할 수 없어야 한다
    - 표시명 간 충돌(동일 마스킹 결과)은 허용한다 — 표시 전용 값이며 식별자가 아니다
    - 용어: 코드·문서에서 `MaskedDisplayName`을 사용한다 (glossary 참조 — "닉네임"/`Nickname`은 태명이 선점한 용어이므로 사용하지 않는다)
  - 아이 태명은 감성적 요소로 활용 가능하지만, 개인 식별 가능성이 있으므로 1차 런치에서는 커뮤니티에 노출하지 않는다
  - 사진 노출 정책 — 자유 일기에는 사진 첨부가 가능하지만, 1차 런치에서는 커뮤니티에 사진을 노출하지 않는다:

    | 항목 | 정책 |
    |------|------|
    | 개인 일기 사진 첨부 | 가능 |
    | 커뮤니티 사진 노출 | 1차 런치 제외 |
    | 커뮤니티 공개 대상 | 텍스트 본문만 |
    | 추후 확장 | 사진 공개 여부를 사용자가 별도 선택하는 방식 검토 |

  - 사진 노출을 1차에서 제외하는 이유:

    | 이유 | 설명 |
    |------|------|
    | 개인정보 보호 | 초음파 사진, 아이 얼굴, 집 배경 등이 노출될 수 있음 |
    | 운영 리스크 감소 | 부적절한 이미지 신고/검수 부담을 줄일 수 있음 |
    | MVP 범위 축소 | 텍스트 기반 커뮤니티로 먼저 검증 가능 |

### AC-009-11: 신고

- **설명**: 게시글과 댓글에 대해 신고를 **접수**할 수 있다. 접수 이후의 운영 처리는 본 AC 범위 밖이다
- **달성 가치**: V-008
- **조건**:
  - 진입점: 게시글 상세의 신고 버튼(AC-009-07)과 댓글의 `⋯` 메뉴 `신고`
  - 신고 사유는 다음 5종 중 선택한다: 부적절한 내용 / 개인정보 노출 / 광고·홍보 / 비방·혐오 표현 / 기타
  - 사유 제출 시 접수가 완료되고 토스트 `신고가 접수되었어요`가 표시된다
  - 같은 사용자가 같은 대상(게시글 또는 댓글)을 중복 신고할 수 없다 — 이미 신고한 대상에서 재시도 시 `이미 신고한 기록이에요` 안내를 표시한다
  - 접수 직후 해당 콘텐츠는 **신고자의 화면에서 숨김** 처리된다 (다른 사용자에게는 영향 없음)
  - **범위 밖 (명시)**: 접수 이후의 운영 검토·제재·자동 숨김 임계값 등 처리 프로세스는 운영 도구 영역으로 본 AC에서 다루지 않는다. 신고된 콘텐츠가 작성자에 의해 삭제되어도 운영 확인이 가능하도록 데이터는 [ENG-012 delete marker](../engineering/record-delete-marker.md)로 보존된다
  - 사용자 차단·검색·상세 필터의 런치 범위는 하단 [1차 런치 범위](#1차-런치-범위-원문-4-19) 표를 단일 소스로 한다 (본 AC에 중복 표기하지 않는다)

### AC-009-12: 커뮤니티 알림 *(1차 런치 제외)*

- **설명**: 커뮤니티 알림(내 글 댓글·대댓글·공감, 신고 처리 결과)은 **1차 런치에서 제외**한다 (2026-08-05 결정)
- **제외 사유**: 원문의 알림 on/off가 설정 탭을 전제하는데 설정 탭 PRD가 보류 상태다. 전제 없는 조건을 확정 AC로 둘 수 없어 기능 자체를 1차에서 제외한다
- **재개 조건**: 설정 탭 명세가 확정되면 알림 이벤트(내 글 댓글 / 내 댓글 대댓글 / 내 글 공감 / 신고 처리 결과)와 on/off를 본 AC 번호로 재정의한다. 번호는 결번 없이 유지한다

### AC-009-13: 빈 상태/예외 상태

- **설명**: 콘텐츠가 없거나 접근할 수 없는 상황마다 명확한 안내 문구를 표시한다
- **달성 가치**: V-002
- **조건**:

  | 상황 | 화면 처리 |
  |------|----------|
  | 공개 기록이 없음 — 커뮤니티 피드 | 아직 공개된 기록이 없어요 |
  | 공개 기록이 없음 — 홈 "다른 엄마들의 기록" 섹션 | 빈 카드 + `첫 기록을 공개해보세요` CTA (AC-009-14 — mock data 없음) |
  | 필터 결과 없음 | 해당 조건의 기록이 아직 없어요 |
  | 네트워크 오류 | 기록을 불러오지 못했어요. 다시 시도해주세요 |
  | 삭제된 글 접근 | 삭제되었거나 볼 수 없는 기록이에요 |
  | 비공개 전환된 글 접근 | 작성자가 비공개로 전환한 기록이에요 |
  | 같은 질문 답변 열람 권한 없음 | 내 답변을 공개하면 같은 질문에 답한 기록을 볼 수 있어요 |

### AC-009-14: 홈 "다른 엄마들의 기록" 섹션 — 이관 수용

- **설명**: 홈 화면 하단에 커뮤니티 공개 기록 카드가 최대 3개 노출되는 섹션의 명세다. 구 PRD-007 AC-007-08에서 이관되었다 (2026-08-05). 화면 내 위치는 [PRD-007 화면 구조](PRD-007-home-screen.md)를 따른다
- **달성 가치**: V-002, V-008
- **참조**: [PRD-007 (홈 화면 구조·이관 스텁)](PRD-007-home-screen.md)
- **조건**:
  - 섹션 타이틀로 **"다른 엄마들의 기록"** 이 표시된다
  - 타이틀 우측에 **">더보기"** 링크가 있고, 탭하면 **커뮤니티 탭**으로 이동한다
  - 피드 카드는 **최대 3개**까지 블록 형태로 노출되며, 가로 스크롤은 없다 (3개 모두 한 화면에 표시)
  - 각 카드는 다음 요소로 구성된다 (AC-009-02 카드와 동일 계열의 축약형):
    - **좌측 상단 — 커뮤니티 표시명**: AC-009-10 마스킹 규칙 (예: `cho***3`)
    - **표시명 옆 — 아이 현황**: 흐린 글씨로 임신 주차 또는 생후 개월/나이 (예: `임신 3주차`, `생후 5개월`)
    - **질문 텍스트**: AI 질문 답변인 경우, 볼드체
    - **본문 미리보기**: 초입부 약 50자 + `...` (정확한 글자 수는 디자인 단계에서 조정)
    - **우측 — 공감 수**: ♥ 하트 아이콘 + 공감 수
  - 카드를 탭하면 해당 기록의 커뮤니티 상세 화면(AC-009-07)으로 이동한다
  - 공개 기록이 0건이면 **mock data를 표시하지 않고** 빈 카드 + `첫 기록을 공개해보세요` CTA를 표시한다 (AC-009-13 — CTA 탭 시 기록 작성 진입). 구 명세의 mock data 조항은 2026-08-05 결정으로 삭제되었다
  - 어떤 기록이 어떤 순서로 노출되는지는 AC-009-02와 동일하게 ENG-007~011 소관이다

## 백엔드 개발 가이드 (원문 4-18)

커뮤니티 피드는 별도 게시글 작성 데이터가 아니라, **기록 데이터 중 공개 상태인 항목을
조회**한다.

필요한 주요 상태값:

| 필드 | 설명 |
|------|------|
| record_id | 기록 ID |
| user_id | 작성자 ID |
| child_id | 아이 ID |
| record_type | `question_answer` / `free_diary` |
| visibility | `private` / `public` |
| question_id | AI 질문 ID, 자유 일기는 null |
| title | 자유 일기 제목 |
| body | 본문 |
| child_status_text | 임신 20주차 / 생후 5개월 |
| like_count | 공감 수 |
| comment_count | 댓글 수 |
| created_at | 작성일 |
| deleted_at | 소프트 딜리트 marker ([ENG-012](../engineering/record-delete-marker.md) 확정 정책) |

주요 API 예시:

| API | 설명 |
|-----|------|
| `GET /community/feed` | 커뮤니티 피드 조회 |
| `GET /community/feed?type=question_answer` | 질문답변 필터 |
| `GET /community/feed?type=free_diary` | 자유일기 필터 |
| `GET /community/records/{recordId}` | 커뮤니티 게시글 상세 |
| `POST /community/records/{recordId}/like` | 공감 |
| `DELETE /community/records/{recordId}/like` | 공감 취소 |
| `GET /questions/{questionId}/public-answers` | 같은 질문 공개 답변 조회 |
| `PATCH /records/{recordId}/visibility` | 공개/비공개 전환 |
| `POST /community/records/{recordId}/comments` | 댓글 작성 |
| `POST /community/comments/{commentId}/replies` | 대댓글 작성 |
| `DELETE /community/comments/{commentId}` | 댓글 삭제 |
| `POST /community/reports` | 게시글/댓글 신고 |
